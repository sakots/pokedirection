# pokedirection

ランダムに表示される2匹から好きなポケモンを10回選ぶと、好みに合う6匹のパーティを提案するWebアプリです。
選んだ10匹の平均能力、サポート・アタッカーの傾向、タイプ分布をもとに選出します。ReactとTypeScriptで実装しています。

## 遊び方

画像・名前・タイプを見て、好きな1匹を選んでください。選択するたびに次の2匹を表示します。
一度表示したポケモンは、選ばなかった方も含めて次の候補から除外します。10回の選択で計20種類を表示し、タイプによる絞り込みは行いません。

10回選び終えると、全ポケモンの標準の姿から重複なしの6匹を選出します。
選んだ10匹とパーティ6匹の平均能力・役割・タイプを比較できます。レーダーチャートの表示対象は、10匹の平均と各ポケモンの種族値です。

「もう一度、出会いにいく」で選択履歴と表示履歴をリセットできます。ページを再読み込みした場合も履歴は消えます。
通信に失敗した場合は、選択履歴を保持したまま再試行してください。読み込みに失敗して表示されなかった候補は除外しません。

## ローカルで起動

Node.js 20.19以上とpnpmを用意してください。Node.js 22系を使う場合は22.12以上が必要です。
APIからデータを取得するため、インターネット接続も必要になります。

```sh
pnpm install
pnpm dev
```

ターミナルに表示されたURLをブラウザで開いてください。通常は`http://localhost:5173`です。

| コマンド | 用途 |
| --- | --- |
| `pnpm test` | 抽選・集計・選出・API取得などのテスト |
| `pnpm typecheck` | TypeScriptの型チェック |
| `pnpm build` | 型チェックと、配信用ファイルの生成 |
| `pnpm preview` | ビルド結果の確認 |

## 公開URLの設定

`.env.example`を参考に、プロジェクト直下の`.env`または`.env.local`へ公開先のURLを設定してください。
サブディレクトリに置く場合は、そのパスまで含めます。

```dotenv
VITE_PUBLIC_URL=https://example.com/pokedirection/
```

公開URLはXへのシェア、OGP、canonicalに使用します。同じ項目を両方のファイルに書いた場合は、`.env.local`が優先です。
開発中に設定を変更した場合は、`pnpm dev`を停止して再起動してください。公開サイトへ反映するには、再ビルドとアップロードが必要です。

公開URLが未設定でもローカルで動作確認できます。Xへのシェアでは閲覧中のURLを使い、localhostやプライベートIPではURLを省略します。
OGPの公開URLには`VITE_PUBLIC_URL`の設定が必要です。ホスティングサービスのビルド環境に設定することもできます。

## FTPで公開

公開URLを設定したら、次のコマンドで配信用ファイルを生成してください。
OGP画像を変更する場合は、先に`public/ogp.png`を差し替えます。

```sh
pnpm build
```

生成された`dist`の中身をすべて、FTPで公開先のディレクトリへアップロードしてください。
`assets`の階層を保ち、次の配置にします。`ogp.png`は画像を配置した場合に出力されます。

```text
公開ディレクトリ/
├── index.html
├── favicon.svg
├── ogp.png
└── assets/
    ├── index-....js
    ├── index-....css
    └── party.worker-....js
```

JavaScript・CSS・アイコン・パーティ選出用Workerの参照先は相対パスです。
ドメイン直下にもサブディレクトリにも配置でき、サーバー側のNode.jsやビルド処理は不要です。

## Xにシェア

パーティ選出後に「Xにシェア」を押すと、Xの投稿画面を新しいタブで開きます。
投稿文には6匹の名前、種族値から見た傾向、アプリのURL、`#pokedirection`を含めます。投稿前に「投稿内容を見る」で内容を確認してください。

Xの投稿画面で内容を確認・編集してから投稿してください。Web Intentを使うため、APIキーは不要です。
共有するURLはアプリの入口です。クエリとフラグメントを除外し、個別の選択結果の復元や画像添付は行いません。

## OGP画像

アプリ紹介用の画像として、1200×630のPNG画像`public/ogp.png`を使います。
画像を更新する場合は、このファイルを差し替えて再ビルドしてください。別のサイズを使う場合は、`vite.config.ts`の`og:image:width`と`og:image:height`も実寸に合わせます。

ビルド時に、OGPと`twitter:card=summary_large_image`のメタタグをHTMLのheadへ出力します。
メタタグはJavaScriptを実行しないクローラーも読み取れる形式です。画像はアプリ共通で、個別のパーティによって変わるものではありません。

設定した公開URLから、`og:url`、canonical、OGP画像の絶対URLを生成します。未設定の場合、画像の参照先は`./ogp.png`です。
公開後は`dist/index.html`のメタタグと、公開先の`ogp.png`を外部から取得できることを確認してください。
Xではカード画像をキャッシュするため、差し替え後の表示更新に時間がかかる場合があります。

## データと選出方法

日本語名・タイプ・種族値・公式アートワークは[PokéAPI](https://pokeapi.co/docs/v2)から取得します。
2択には種族一覧と各種族の標準の姿を使います。パーティ候補の取得は[GraphQL v1beta2](https://pokeapi.co/docs/graphql)への1回のPOSTです。
APIのレスポンスはメモリとlocalStorageに24時間キャッシュします。

パーティ選出では、6匹の平均能力が選んだ10匹に近づく組み合わせを探します。役割とタイプの好みも反映します。
対戦相性や技構成は評価せず、能力の形と数値の大きさを比較します。サポート・アタッカーの判定は種族値から見た独自の目安で、実際の役割は技構成によって変わります。

### チャートの計算式

種族値にはPokéAPIの`stats[].base_stat`を使います。集計では各選択を1匹と数え、同じポケモンを複数回選んだ場合も選択回数を反映します。

| 項目 | 計算方法 |
| --- | --- |
| 攻撃／防御 | 「こうげき＋とくこう」と「ぼうぎょ＋とくぼう」をそれぞれ合計して比較 |
| 物理／特殊 | 「こうげき」と「とくこう」をそれぞれ合計して比較 |
| サポート／アタッカー | 各ポケモンの「HP・ぼうぎょ・とくぼうの平均」と「こうげき・とくこうの高い方」をそれぞれ合計して比較 |
| 傾向ラベル | 片側が55%を超えればその側に寄り、それ以外はバランス型 |
| タイプ分布 | 各タイプを持つポケモンの数。複合タイプは両方に1匹ずつ加算 |

能力・役割の割合は種族値の比率で、ポケモンの人数比ではありません。

### 6匹を選ぶアルゴリズム

選んだ10匹に候補を限定せず、全種族の標準の姿から6種類を選びます。
6匹全体と10匹の傾向の差を、次の重みで評価します。

| 評価項目 | 重み | 誤差の計算 |
| --- | --- | --- |
| 平均種族値 | 65% | 6軸の平均種族値について相対誤差の二乗平均を使用。各軸の分母は目標種族値と40の大きい方 |
| サポート／アタッカー | 20% | サポート比率の差を0.5で割って二乗 |
| タイプ分布 | 15% | 各タイプを持つポケモンの割合の差を二乗し、全18タイプで合計して4で割る。複合タイプは両方に加算 |

探索では複数の開始候補から6匹を選び、1匹ずつ交換して誤差を減らします。
改善が止まった場合は、候補を絞った2匹同時の交換も試します。計算はWeb Workerで行うため、探索中も画面を操作できます。

候補と6匹という制約により、目標の能力と完全には一致しない場合があります。
近似探索のため、全組み合わせの中で誤差が最小になる保証はありません。候補の取得に失敗した場合は、10回の選択を保持したまま再選出できます。
