# pokedirection

全ポケモンからランダムに表示される2匹のうち、好きな1匹を10回選ぶReact＋TypeScript（TSX）アプリです。
10回の選択で得た好みの傾向から、全ポケモンの標準の姿を候補に6匹のパーティを選出します。

## 起動

Node.js 20.19以上（22系の場合は22.12以上）とpnpmを使用します。

```sh
pnpm install
pnpm dev
```

表示されたURL（通常は `http://localhost:5173`）をブラウザで開いてください。

```sh
pnpm test     # 抽選・選択回数・API取得とキャッシュの検証
pnpm typecheck # TypeScriptの型チェック
pnpm build    # dist/ に配信用ファイルを生成
pnpm preview  # ビルド結果を確認
```

## 選択の流れ

- 毎回、今回まだ表示していないポケモンの種族からランダムな2匹を表示します。10回で計20種類に出会えます。
- 選ばなかった方も次回以降の2択から除外します。タイプによる絞り込みは行いません。
- 「もう一度、出会いにいく」で表示履歴もリセットします。読み込みに失敗して表示されなかった候補は除外しません。
- 画像、日本語名、タイプを見て1匹を選ぶと、次の2匹が表示されます。
- 10回目の選択で完了し、10匹の選択履歴を確認できます。「もう一度、出会いにいく」で最初からやり直せます。
- 完了後に攻撃／防御、物理／特殊、サポート／アタッカーの傾向、種族値のレーダーチャート、タイプ分布を表示します。
- 全ポケモンから重複なしの6匹を自動選出し、10匹と6匹の平均種族値・役割・タイプ分布を比較します。
- レーダーチャートは10匹の平均と各ポケモンの表示を切り替えられます。
- 通信に失敗した場合は、選択履歴を保持したまま再試行できます。

## チャートの集計

種族値はPokéAPIの `stats[].base_stat` を使用します。同じポケモンを複数回選んだ場合も各選択を集計します。

- 攻撃／防御：こうげき＋とくこう と ぼうぎょ＋とくぼう の合計の比率。
- 物理／特殊：こうげき と とくこう の合計の比率。
- サポート／アタッカー：各ポケモンの（HP＋ぼうぎょ＋とくぼう）÷3 と、こうげき・とくこうの高い方をそれぞれ合計した比率。
- 傾向ラベル：片側が55%を超えればその側に寄り、それ以外はバランス型。
- タイプ分布：複合タイプは両方に1匹ずつ加算します。

サポート／アタッカーは能力から見た独自の目安です。技・特性を使った役割判定ではなく、実際の役割は技構成によって変わります。割合は人数比ではありません。

## 6匹のパーティ選出

選択した10匹に候補を限定せず、全種族の標準の姿から6種類を選びます。
候補一覧は[PokéAPI GraphQL v1beta2](https://pokeapi.co/docs/graphql)の1回のPOSTで取得し、24時間キャッシュします。

選出は6匹の組み合わせ全体について、以下の誤差を重み付きで最小化する近似探索です。

- 平均種族値（65%）：6軸の平均が10匹の平均に近づくよう、各軸の相対誤差の二乗平均を使用します。分母は目標種族値と40の大きい方です。
- サポート／アタッカー（20%）：従来の計算式によるサポート比率の差を0.5で割って二乗します。
- タイプ分布（15%）：各タイプを持つポケモンの割合の差を二乗し、全18タイプで合計して4で割ります。複合タイプは両方を集計します。

複数の開始候補から6匹を構築し、1匹ずつの交換で誤差を減らします。改善が止まった場合は候補を絞った2匹同時の交換も試します。Web Worker内で計算するため、画面操作を妨げません。
能力の形だけでなく数値の大きさも対象とします。候補と6匹という制約により完全一致しない場合があり、全組み合わせの厳密な最適解を保証するものではありません。
タイプは好みの分布を再現する目的で使い、対戦相性や技構成は評価しません。取得失敗時も10回の選択を保持したまま再選出できます。

## データ

[PokéAPI](https://pokeapi.co/docs/v2)の種族一覧を取得し、各種族の標準の姿を表示します。
日本語名・タイプ・公式アートワークもAPIから取得します。APIレスポンスはメモリとlocalStorageに24時間キャッシュします。
APIへのアクセスにはインターネット接続が必要です。選択履歴はページを再読み込みするとリセットされます。
